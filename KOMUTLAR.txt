 0. ÖNCE BUNU OKU

KOMUT NASIL ÇALIŞTIRILIR (sunucuda, SSH / cPanel Terminal)
  cPanel → "Setup Python App" ekranının üstünde şuna benzer bir satır yazar:

      source /home/KULLANICI/virtualenv/PROJE_KLASORU/3.10/bin/activate && cd /home/KULLANICI/PROJE_KLASORU

  Bu satırı terminale yapıştır. Artık bütün komutlar şöyle çalışır:

      python manage.py KOMUT_ADI [seçenekler]

  Yerelde (Mac'te) proje klasöründe:

      .venv/bin/python manage.py KOMUT_ADI [seçenekler]

  Bir komutun bütün seçeneklerini görmek için:   python manage.py KOMUT_ADI --help

İŞARETLER (aşağıda her komutun yanında)
  [YAYIN]      Yayına alırken / güncellerken sunucuda çalıştırılır.
  [CRON]       Zamanlanmış iş: cPanel → Cron Jobs'a eklenir, kendiliğinden çalışır.
  [SUNUCU]     Gerektiğinde sunucuda elle çalıştırılır.
  [YEREL]      Yalnızca kendi bilgisayarında çalıştır; sunucuda gerek yok.
  [TEHLİKELİ]  Veri siler ya da değiştirir. Önce yedek al, önce kuru deneme yap.
  [ÜCRETLİ]    Yapay zekâ API'sine (OpenRouter / Gemini) para harcayan çağrı yapar.

ÜÇ ALTIN KURAL
  1) Önce kuru deneme. Veri değiştiren komutların neredeyse hepsinde --dry-run var
     (veritabani yukle'de bu varsayılandır; yazmak için --uygula gerekir). Önce kuru dene,
     raporu oku, sonra gerçekten çalıştır.
  2) Önce yedek. Canlıda veri değiştirmeden önce:
         python manage.py veritabani indir ~/veritabani-yedekleri/yedek-TARIH.sqlite3
  3) Değişiklikten sonra uygulamayı yeniden başlat:
         touch tmp/restart.txt
     (Passenger kodu ve .env'i ancak yeniden başlayınca okur.)

 1. YAYINA ALIRKEN — SIRAYLA
=====================================================================================

Adım 1 — Kodu yükle ve paketleri kur  [YAYIN]
      git pull                               (ya da dosyaları cPanel ile yükle)
      pip install -r requirements.txt
  Ne yapar: Projenin ihtiyaç duyduğu Python paketlerini kurar (Django, mysqlclient,
  pywebpush, pymupdf, google-genai …).
  Neden önemli: Eksik paket olursa site açılmaz ya da bildirim / PDF / yazı değerlendirme
  çalışmaz. requirements.txt değiştiğinde her seferinde tekrar çalıştır.

Adım 2 — .env dosyasını hazırla  [YAYIN]
  Proje klasöründeki .env dosyasında en az şunlar olmalı (değerleri sohbete / git'e yazma):
      DEBUG=False
      SECRET_KEY=...
      SITE_ADRESI=https://...
      DB_ENGINE=django.db.backends.mysql
      DB_NAME=...  DB_USER=...  DB_PASSWORD=...  DB_HOST=localhost
      GEMINI_API_TOKEN=...
      GEMINI_MODEL=gemini-3.6-flash
      GEMINI_FALLBACK_MODELS=gemini-3.7-flash,gemini-3.8-flash
      YAYIN_DILLERI=tr,en        (sunucuda "de" YOK)
      EKLENTI_ADRESI=...         (Chrome Web Store adresi; yoksa boş)
      EKLENTI_KIMLIKLERI=...     (Chrome eklentisinin kimliği; eklentinin siteye bağlanabilmesi için)
      GOOGLE_CLIENT_ID=...  GOOGLE_CLIENT_SECRET=...     (Google ile giriş)
      EMAIL_HOST_USER=...   EMAIL_HOST_PASSWORD=...      (şifre sıfırlama, doğrulama e-postaları)
      KVKK_VERI_SORUMLUSU=...  KVKK_ILETISIM_EPOSTASI=... (aydınlatma metninde görünür)
      OZEL_DEPO=/home/KULLANICI/ozel_depo   (kullanıcı PDF'leri; web kökünün DIŞINDA olmalı)
      TEXT_DAILY_LIMIT=3  YAZMA_DAKIKADA_EN_COK=4        (yazı değerlendirme sınırları; isteğe bağlı)
  Neden önemli: DEBUG=False olmadan site hata ayrıntılarını herkese gösterir.
  VAPID anahtarlarını elle yazma; Adım 6'daki komut yazar.

Adım 3 — Tabloları kur / güncelle  [YAYIN]
      python manage.py migrate
  Ne yapar: Veritabanı tablolarını koddaki modellere göre kurar ya da günceller
  (yeni tablo, yeni sütun). Uygulanmamış migration'ları sırayla uygular.
  Neden önemli: Kod yeni bir sütun beklerken veritabanında yoksa ilgili sayfa hata verir.
  Her kod güncellemesinden sonra çalıştır. Durumu görmek için: python manage.py showmigrations
  NOT (17 Ekim): yerel veritabanında words 0029 ve 0030 henüz uygulanmamış; yerelde de
  bir kez "migrate" çalıştır.

Adım 4 — Veriyi canlıya taşı (YALNIZCA İLK YAYINDA)  [YAYIN] [TEHLİKELİ]
  Yerelde, yerel veritabanının tam kopyasını al:
      .venv/bin/python manage.py veritabani indir ilk-yayin.sqlite3
  Dosyayı sunucuya yükle (web kökünün DIŞINA), sonra sunucuda:
      python manage.py veritabani yukle ilk-yayin.sqlite3 --hepsi            (kuru deneme)
      python manage.py veritabani yukle ilk-yayin.sqlite3 --hepsi --uygula   (EVET yazmanı ister)
  Ne yapar: Canlıdaki BÜTÜN tabloları boşaltıp dosyadakiyle doldurur.
  Neden önemli: Sözlük, okumalar, listeler, konular, egzersiz havuzları canlıya böyle geçer.
  DİKKAT: --hepsi kullanıcı tablolarını da siler. Yalnızca ilk yayında, site boşken kullan.
  Sonra dosyayı sunucudan sil (içinde kullanıcı e-postaları ve şifre özetleri var).
  Ayrıntı: Bölüm 4.

Adım 5 — Statik dosyaları topla  [YAYIN]
      python manage.py collectstatic --noinput
  Ne yapar: CSS, JavaScript, ikonlar, yazı tipleri, service worker gibi dosyaları
  STATIC_ROOT klasörüne (staticfiles_root/) kopyalar; web sunucusu onları buradan verir.
  Neden önemli: DEBUG=False'ta Django statik dosya vermez. Çalıştırmazsan site stilsiz
  ve bozuk görünür. Her CSS / JS değişikliğinden sonra tekrar çalıştır.

Adım 6 — Bildirim anahtarlarını üret (YALNIZCA BİR KEZ)  [YAYIN]
      python manage.py vapid_anahtari_uret --eposta ADRESIN@ornek.com
  Ne yapar: Web push bildirimleri için VAPID anahtar çiftini üretip DOĞRUDAN .env'e yazar
  (ekrana basmaz).
  Neden önemli: Anahtar olmadan telefon bildirimleri gitmez.
  DİKKAT: Bir kez üretilir. .env'de dolu anahtar varsa komut dokunmaz; anahtarı elle
  değiştirirsen bütün kullanıcıların bildirim abonelikleri geçersiz olur.

Adım 7 — Yönetici hesabı  [YAYIN]
      python manage.py createsuperuser
  Ne yapar: /admin/ paneline girebilen bir hesap açar.
  Neden önemli: Veriyi tarayıcıdan denetlemek, istatistik ekranı ve acil düzeltmeler için.
  (Veriyi yerelden taşıdıysan yerel yönetici hesabın da gelmiştir; gerekmeyebilir.)

Adım 8 — Yayın öncesi güvenlik denetimi  [YAYIN]
      python manage.py check --deploy
  Ne yapar: Django'nun canlı ortam ayarlarını denetler (DEBUG, HTTPS, çerez güvenliği,
  SECRET_KEY, HSTS …) ve uyarı listesi verir.
  Neden önemli: Açık bir güvenlik ayarını yayından önce yakalar. Uyarı kalmamalı
  (kalanları bilerek kabul ettiğinden emin ol).

Adım 9 — Cron işlerini ekle  [YAYIN]
  Bölüm 3'teki satırları cPanel → Cron Jobs'a ekle. Önce her komutu --dry-run ile elle dene.

Adım 10 — Uygulamayı yeniden başlat  [YAYIN]
      touch tmp/restart.txt
  Sonra siteyi aç; ana sayfa, sözlük araması, Learn & Pass ve yazı gönderme çalışıyor mu bak.

Adım 11 — Arama motorlarına aç  [YAYIN]
      python manage.py dizine_ac                     (durum: kaç sayfa açık)
  Ayrıntı: Bölüm 5. Google Search Console'a site haritasını (/sitemap.xml) ekle.

 4. CANLI VERİTABANI <-> SQLITE DOSYASI   (veritabani indir / yukle)
=====================================================================================

Amaç: Canlıdaki veriyi bilgisayarına indirip yerelde düzenlemek (sözlük düzeltmeleri, yeni
kelimeler, listeler …) ve düzenlenmiş içeriği canlıya geri koymak. Kod:
LearnVocab/veritabani_esitleme.py

4.1  indir   [SUNUCU]
      python manage.py veritabani indir ~/canli-17ekim.sqlite3
  Ne yapar: Canlı veritabanının (MySQL) BÜTÜN tablolarının tam kopyasını YENİ bir SQLite
  dosyasına yazar. Dosyaya bir künye eklenir: alındığı tarih, migration durumu ve her
  içerik tablosunun parmak izi (yüklerken "canlı bu arada değişti mi" diye bakmak için).
  Okuma tek işlemde yapılır; site çalışırken alınabilir, kullanıcılar etkilenmez.
  Var olan bir dosyanın üstüne yazmaz.
  DİKKAT: Dosyada kullanıcıların e-postaları ve şifre özetleri var. Web kökünün (public_html)
  DIŞINA yaz, indirince sunucudan sil, kimseyle paylaşma.

  Yerelde dosyayla çalışmak:
      DB_NAME=canli-17ekim.sqlite3 .venv/bin/python manage.py runserver
      DB_NAME=canli-17ekim.sqlite3 .venv/bin/python manage.py shell -c "..."   (düzeltme betikleri)

4.2  yukle   [SUNUCU] [TEHLİKELİ]
      python manage.py veritabani yukle ~/canli-17ekim.sqlite3              (KURU DENEME: yalnızca rapor)
      python manage.py veritabani yukle ~/canli-17ekim.sqlite3 --uygula     (gerçekten yazar)
  Ne yapar: Dosyadaki İÇERİK tablolarını canlıya eşitler: yeni satır eklenir, değişen
  güncellenir, dosyada olmayan silinir. İçerik tabloları: sözlük (kelimeler, anlamlar,
  örnekler, eş dizimler, kalıplar, çekimler, eş/zıt/basit bağları, aileler, yanlış dostlar),
  ifadeler, konular (kategoriler), hazır listeler, okuma kütüphanesi, egzersiz havuzları
  (bağlaç cümleleri, eş dizim çeldiricileri), seviye testi havuzları, diyaloglar.
  KULLANICI tablolarına HİÇ dokunmaz: hesaplar, listeler (Listem), seri, yazılar, okuma
  ilerlemesi, egzersiz sonuçları, bildirim abonelikleri, oturumlar. Yani dosyayı indirdikten
  sonra canlıda olan her şey (yeni kayıtlar, listeye eklenen kelimeler, seriler) korunur.
  Silinen bir kelimeye bağlı kullanıcı kayıtları (o kelime birinin listesindeyse) Django'nun
  kurallarıyla birlikte silinir; kuru denemede "birlikte silinecek kullanıcı kayıtları"
  başlığında sayıları görünür. Bunu mutlaka oku.

  Güvenlik önlemleri (kendiliğinden):
    - Varsayılan kuru denemedir. Her şey yapılır, sonra geri alınır; yalnızca rapor kalır.
    - --uygula ile önce canlının TAM yedeği alınır: ~/veritabani-yedekleri/yedek-TARIH.sqlite3
    - Dosyanın ve canlının migration'ları farklıysa durur ("önce migrate çalıştır").
    - Dosya indirildikten sonra canlıda bir içerik tablosu değiştiyse durur (birisi canlıda
      da sözlük düzenlediyse, onun işini ezmemek için). Bilerek ezmek için: --zorla
    - Hepsi tek işlemde yapılır; bütünlük denetimi geçmezse HİÇBİR şey yazılmaz.
    - Yüklemeden sonra dosyanın künyesi güncellenir: aynı dosyayla çalışmaya devam edip
      yeniden yükleyebilirsin.
    - Yüklemeden sonra önbellek temizlenir. Sonra:  touch tmp/restart.txt

  Seçenekler:
    --uygula             gerçekten yaz
    --zorla              canlıda indirmeden beri değişen içerik tablolarını da dosyadakiyle ez
    --hepsi              BÜTÜN tabloları (kullanıcılar dahil) dosyadakiyle değiştir. YALNIZCA
                         ilk taşıma için. "EVET" yazmanı ister (--evet ile sormaz).
    --yedek-klasoru YOL  tam yedeğin yazılacağı klasör (varsayılan ~/veritabani-yedekleri)

4.3  Önerilen düzen
  1) Sunucuda indir, dosyayı bilgisayarına al, sunucudakini sil.
  2) Yerelde düzenle (DB_NAME=dosya ile). Bu sırada canlıda SÖZLÜĞÜ düzenleme (admin'den bile);
     yoksa yüklerken "canlı değişmiş" uyarısı alırsın.
  3) Kod değişikliği (yeni migration) varsa önce kodu yayına al ve iki tarafta migrate çalıştır:
     sunucuda "python manage.py migrate", yerelde "DB_NAME=dosya .venv/bin/python manage.py migrate".
  4) Dosyayı sunucuya yükle, kuru dene, raporu oku, --uygula, touch tmp/restart.txt, dosyayı sil.

4.4  Geri dönüş
  Yükleme bir şeyi bozduysa: --uygula'dan önce alınan tam yedek ~/veritabani-yedekleri/'nde.
  O yedekle bütün canlıyı geri getirmek için (O ANA KADARKİ kullanıcı etkinliği de geri gider):
      python manage.py veritabani yukle ~/veritabani-yedekleri/yedek-TARIH.sqlite3 --hepsi --uygula
  Yalnızca içeriği geri almak için --hepsi'siz yükle (kullanıcı verisi korunur; yedeğin künyesi
  eski olduğu için --zorla gerekir).

4.5  Geliştirici notu
  Yeni bir model (tablo) eklenince LearnVocab/veritabani_esitleme.py'deki ICERIK ya da
  KULLANICI listesine yazılmalı; yazılmazsa komut çalışmaz ve test (test_veritabani_esitleme)
  uyarır.

 11. SORUN ÇIKARSA
=====================================================================================

  Site açılmıyor (500 hatası)
    → cPanel → Setup Python App → log dosyasına bak. Çoğu zaman: eksik paket (pip install),
      uygulanmamış migration (migrate) ya da .env hatası.
  Sayfa stilsiz görünüyor
    → python manage.py collectstatic --noinput  ve  touch tmp/restart.txt
  "no such column" / "Unknown column" hatası
    → python manage.py showmigrations, sonra python manage.py migrate
  Yazılar değerlendirilmiyor ("Henüz değerlendirilmedi")
    → python manage.py list_gemini_models (model adı geçerli mi?), Gemini günlük kotası (günde 20)
      dolmuş olabilir; cron ertesi gün dener. Log: ~/logs/yazilari_yeniden_dene.log
  Bildirim gitmiyor
    → .env'de VAPID anahtarları dolu mu, cron 15 dakikada bir çalışıyor mu,
      python manage.py bildirim_gonder_hatirlatma --dry-run
  Yüklemeden (veritabani yukle) sonra bir şey bozuldu
    → ~/veritabani-yedekleri/'ndeki son yedekle geri dön (Bölüm 4.4).
  Değişiklik sitede görünmüyor
    → touch tmp/restart.txt (Passenger yeniden başlamadan kodu ve .env'i okumaz)
